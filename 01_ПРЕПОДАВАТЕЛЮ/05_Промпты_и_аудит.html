ИИ как помощник и оппонент: проверяемые задания

Эти запросы можно использовать в разных LLM. Они не требуют особой модели или определённой подписки. В лабораторной разрешено работать без доступа к модели, проверяя готовое предложение из задания. Не отправляйте в общедоступные сервисы реальные персональные и внутренние данные.

Тема 4. Построить предварительную политику очистки

Вход для модели: только описание полей, выбранные проблемные строки и назначение будущего анализа.

Я исследую синтетическую таблицу измерений микроклимата в учебных помещениях. Единица наблюдения — показание датчика в определённое время. Поля: record_id, room_code, observed_at, co2_ppm, temp_c, people_count, vent_mode. Составь таблицу возможных действий над следующими проблемами: значение CO₂=0, CO₂=4200, пропуск CO₂, две полные копии одной строки, одинаковый record_id с разными CO₂, код помещения отсутствует в справочнике. Для каждой строки дай действие, основание, риск потери информации и проверку. Не исправляй значения выдуманными измерениями, не делай операций с данными, отделяй факт от гипотезы.

Что необходимо проверить без модели: правило для каждой ситуации; наличие оснований; необходимость карантина; насколько предложения воспроизводимы на новых строках.

Тема 4. Попросить ИИ написать формулу

Объясни, как привести строки вида «21,4», «1250», «1 250» к числам в Excel/Calc или pandas. Дай проверку на трёх строках и объясни, как обрабатывать пустые строки и неожиданные слова. Не используй значение 0 вместо ошибки разбора.

Проверка: три фиксированных теста, один пустой ввод, один ошибочный ввод. Нельзя принимать без теста «формула работает».

Тема 5. Две целевые схемы

У меня синтетические измерения аудитории: код комнаты, количество людей, вместимость, CO₂ в ppm, температура в °C, время, тип комнаты. Цель А — человекочитаемый отчёт управляющему; цель Б — подготовка для будущего поиска похожих состояний. Предложи по отдельности схемы признаков для А и Б. Для каждого признака укажи смысл, тип, единицы, формулу и ограничения. Не обучай модель, не нормализуй ID как количество, укажи параметры масштабирования, необходимые для новой партии.

Проверка: наличие производной доли заполнения с нулевым знаменателем; безопасная обработка незнакомых категорий; отсутствие неявного «подглядывания» в будущее.

Тема 5. Извлечение структуры из текста

Для каждого сообщения выдели поля message_id, topic, intent, needs_review. Возможные topic: воздух, посещаемость, расписание, датчик, условия, система. Возможные intent: жалоба, действие, сомнение, сообщение, неисправность, нейтрально, нет данных. Не выдумывай срок устранения и реальное состояние оборудования. Если контекст неоднозначен, ставь needs_review=true. Выводи только таблицу со всеми исходными идентификаторами.

Проверка: сохранены все ID, метки только из словарей, 8–10 строк перепроверены человеком. При обнаружении ошибок обновлять правила аннотации и сравнивать результат на той же контрольной подборке.

Протокол аудита ИИ

Для каждого использования заполните четыре поля: 1) исходный вопрос модели и доступный ей контекст; 2) конкретное предложение; 3) проверка без доверия к тексту модели; 4) принятое решение с причиной. Скриншот чата допускается как дополнительное свидетельство, но не заменяет результата, проверку и журнал.

Цель: научить студента видеть в ИИ полезного участника процесса подготовки данных, не превращая второкурсную практику в разработку автономных агентных систем.
